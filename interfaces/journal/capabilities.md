# 监理日记三入口处理语义

状态：`confirmed`。用户于 2026-11-12 明确批准本方案并指定三个路径；正式机器契约见 [journal.openapi.json](../openapi/journal.openapi.json)。

## 1、需求与方案

用户提出三个入口：组合处理、纯 OCR、纯工作内容拆分；明确要求纯 OCR 返回识别框、坐标、置信度和拆分前内容。

| 入口 | 输入 | 输出与行为 |
| --- | --- | --- |
| 现有 `POST /ocr/journal` | 既有图片请求 | 继续执行 OCR、规则/Agent 拆分和结果组装；请求、成功响应及错误语义不变 |
| 新增 `POST /ocr/journal/recognize` | 沿用现有图片请求的 `path`、`img`、`taskId` 及优先级、数据池限制 | 返回全部检测框、栏目识别结果、置信度和几何位置；不执行规则拆分或调用语言模型 |
| 新增 `POST /ocr/journal/process` | 完整 `main_work` 文本 | 复用规则优先、Agent 兜底及关键数据校验；返回 `construction`、`witness`、`patrol` |

考虑过仅保留组合入口、三个入口共存、强制调用方分步调用三种方案。建议三个入口共存：业务保持一次请求，测试和人工校对后的文本重处理可以独立调用；代价是维护两个新增接口的契约。

不拆部署服务、不引入数据库、持久会话或任务轮询；内部直接调用公共函数，不在同一应用内通过 HTTP 串联接口。

## 2、纯 OCR 返回结构建议

成功使用 OCR 既有包装：`{"status":200,"message":"识别完成","data":...}`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `data.taskId` | string/null | 沿用现有回显规则 |
| `data.documentType` | string | 固定 `supervision_diary` |
| `data.image.width`、`height` | integer | EXIF 校正后、缩小前的图片宽高 |
| `data.image.coordinateSpace` | string | 固定 `exif_corrected_original` |
| `data.tablePolygon` | 四点数组 | 检测到的表格四角 |
| `data.boxes` | array | 本次 OCR 返回的全部检测框，包括标签、未归属框以及随后被字段去重逻辑排除的框 |
| `data.fields` | array | 模板全部 11 个栏目，空栏目也保留 |

`boxes` 中每项包含：

- `id`：仅本响应内唯一的 string，用于栏目引用，不作为跨请求稳定标识。
- `text`：OCR 返回的文字，不以栏目清洗后的值覆盖。
- `confidence`：OCR 引擎识别分数，范围 `[0,1]`，不代表业务正确率。
- `polygon`：文字四边形。

`fields` 中每项包含：

- `key`：沿用内部既有栏目编码 `project`、`number`、`supervision_org`、`recorder`、`weather`、`position`、`date`、`reviewer`、`main_work`、`issues`、`next_day_plan`。
- `label`：模板栏目名称。
- `text`：栏目提取后的拆分前文字；空栏目为 null。保留既有去印刷标签、占位清理、日期归一与阅读顺序处理；不执行工作内容分类或模型改写。
- `confidence`：沿用既有字段计算口径，取去重并排除纯标签后的有效框分数算术平均，保留三位小数；没有有效框时为 `0.0`。它不是新增的字段正确率估计。
- `polygon`：模板栏目值区映射到图片后的四边形，区别于实际检测到的文字框。
- `boxIds`：归属该栏目的检测框 ID；空数组表示无已接受的归属框。原始框仍保留在顶层 `boxes`，因此不是按此数组重新拼接就必然等于 `text`。
- `ambiguous`：是否存在归属歧义或栏目来源覆盖不足，沿用现有判定。
- `visibleFraction`：栏目在来源图片中的有效覆盖比例，范围 `[0,1]`。

`key=main_work` 的 `text` 应与组合接口实际送入拆分步骤的完整文本一致：在完整性检查通过时按已有片段保留换行，否则使用完整栏目原文；不先去掉施工、旁站或巡视标题。它可以直接作为文本拆分接口的 `main_work` 输入。

示意（仅展示一个栏目及一个文字框，非完整成功响应）：

```json
{
  "boxes": [
    {
      "id": "box-1",
      "text": "施工情况：K1+100填筑。",
      "confidence": 0.96,
      "polygon": [[120, 400], [700, 410], [699, 450], [119, 440]]
    }
  ],
  "fields": [
    {
      "key": "main_work",
      "label": "当日主要监理工作情况",
      "text": "施工情况：K1+100填筑。",
      "confidence": 0.96,
      "polygon": [[100, 380], [900, 390], [890, 1000], [90, 990]],
      "boxIds": ["box-1"],
      "ambiguous": false,
      "visibleFraction": 1.0
    }
  ]
}
```

## 3、坐标约定

- 所有对外几何坐标使用同一个坐标系：EXIF 方向校正后、缩小前的图片像素坐标；左上为原点，x 向右，y 向下，允许浮点数。
- 四点按校正画布上的左上、右上、右下、左下顺序映射回图片，保持环绕顺序；图片倾斜时不按映射后的最小 x/y 重新排序。
- 现有 OCR 框位于透视校正画布，输出前通过逆单应变换并还原缩放比例；不能直接把画布坐标当作原图坐标返回。
- 模板值区可能延伸到图片之外，坐标不强行裁剪，以免把来源缺失伪装成完整栏目；由 `visibleFraction` 表达覆盖情况。
- 调用方显示的图片必须采用 EXIF 校正后的方向；叠加到缩略图时按显示宽高等比换算。

## 4、拆分入口与内部边界

文本拆分入口建议只接收必填 string `main_work`，不接收图片、OCR 坐标、历史或会话。空文本及纯标题文本返回三个 null；必填字段缺失和类型不合法返回 422。

成功直接返回三个必填可空字段，采用三个字段的直接响应，不使用 data 包装。保留现有规则完整覆盖时直接返回、规则不足时调用 Agent、关键数据校验、并发、总预算及模型回退策略；模型路径的 4000 字符保护不变，不把它改成所有输入的统一长度限制。拆分失败保持受控 502 和 detail 包装，沿用既有固定错误文案“监理日志主要工作情况无法可靠拆分，请核对照片后重试”。

为使文本测试与组合流程一致，将“取得并合并 main_work 栏目文字”和“对完整文本拆分”划清边界；组合接口与文本接口共享后一项，禁止文本接口绕过校验直接调用 Agent.generate。

独立调用拆分入口可能命中规则；实际模型能力通过评测脚本直接调用 Agent 并复用结果校验验证，不新增强制走模型的公开开关。

纯 OCR 入口沿用既有图片错误处理：输入校验 422；路径、解码及表格定位等受控错误 400；OCR 模型或资源不可用 503。表格定位失败在 OCR 前结束，不返回全空成功。该入口不依赖语言模型推理是否可用。

## 5、实现影响与验收标准

现有 `JournalRecognition` 仅保留栏目归属后的框，完整 OCR 检测结果在字段匹配过程中丢失。新增输出需要在请求局部保留全部检测框和关联关系，不得为输出原始框再执行一次 OCR，也不得改变现有字段归属、清洗、拆分算法或组合接口行为。

验收要求：

1. 组合接口请求、完整响应和错误语义保持既有契约。
2. 纯 OCR 每次请求仅执行一次 OCR，不调用语言模型或工作内容分类；返回全部检测框及 11 个栏目。
3. 使用倾斜图、EXIF 旋转图和超大缩放图核对文字框、栏目框及表格框叠加位置。
4. 验证未归属框、重复框、纯标签框、归属歧义与来源覆盖不足的可观察结果。
5. 从同一次识别结果导出 main_work，再调用共享拆分逻辑，验证输入与组合流程一致；规则和模型路径分别验收，模型生成结果不要求逐字确定性。
6. 验证真实图片的文字保真和栏目归属；置信度高、结构合法或 HTTP 200 均不代替内容核对。
7. 验证并发请求资源与返回数据隔离，保留取消、超时和受控错误行为。

旧 `/ocr/daily-logs-new` 路由删除，不重定向。调用方需要更新路径；组合入口请求、响应及错误语义不变。三个入口均通过已批准契约验收，其他接口的完整草案状态不变。
