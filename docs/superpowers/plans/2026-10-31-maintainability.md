# 保持行为的可维护性重构计划

**目标：** 保持 API、模型协议、业务规则、配置和脚本入口不变，改善资源管理、HTTP 错误边界和验收脚本的职责组织。

**依据：** 本次用户的重构要求及根目录 AGENTS.md。直接在用户指定的当前工作区实施，保留既有未跟踪内容，不提交、切换分支或修改依赖。

**技术栈：** Python 3.12、FastAPI、httpx、LangChain 1.x、pytest、uv、Ruff。

## 审查与取舍

- 主 API 已有共享 Agent 基类、统一运行时、独立提示词和请求局部历史；保留这些边界，不增加仓储层或业务接口层。
- `ModelService` 的异步客户端释放异常会阻断同步客户端释放；创建异步客户端失败也会遗留先创建的同步客户端。先用回归测试证明，再保证异常路径释放资源。
- `create_app()` 同时包含资源初始化、七类异常注册和六个路由。只把 HTTP 异常注册提取为一个内聚模块，保留生命周期和路由在原入口。
- `verify_agents.main()` 混合请求记录、日志数据集、意图数据集和会话验收。将请求记录及各场景拆成同文件内的函数/类，保留报告字段、顺序、错误传播和兼容入口。
- OCR 属于已有未跟踪内容，依赖环境独立。纳入只读审查，缺乏运行依赖和回归数据时不直接改动算法、缓存和文件访问策略。

## 全局约束

- 不修改业务提示词、JSON Schema、URL、错误详情、状态码、超时、模型参数、历史预算和身份传递规则。
- 不添加依赖，不修改 `.env`、锁文件、用户数据、隧道配置或 OCR 现有内容。
- FastAPI 仍管理注入的模型服务客户端生命周期。
- 新增测试放在现有 `tests/`，不搬动测试目录以掩盖 AGENTS.md 中旧命令的不匹配。

## 验证重点

1. 异步关闭失败或取消时，同步客户端仍被关闭；原异常继续传播。
2. Agent 初始化失败时，已有客户端被关闭。
3. 所有模型异常保持原状态码和安全详情；参数错误不泄露输入、身份或上下文。
4. 重构前后完整 OpenAPI 文档一致。
5. 验收脚本的实际请求、响应、失败报告和检查顺序保持兼容。
